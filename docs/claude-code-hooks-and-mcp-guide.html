2. Claude Code Hooks 完全解析

2.1 什麼是 Hook？（類比解釋）

想像 Claude Code 是一間餐廳的廚師：

餐廳類比Claude Code 對應Hook 角色
客人點餐使用者輸入 promptUserPromptSubmit — 可以拒收不合理的訂單
廚師準備切菜Claude 要呼叫 Edit 工具PreToolUse — 檢查食材是否安全
菜做好了工具執行完成PostToolUse — 加上擺盤（格式化）、記錄品質
廚師想下班Claude 要停止回應Stop — 檢查所有訂單是否完成

技術定義：Hook 是一個 shell 腳本（或 HTTP endpoint），在 Claude Code 生命週期的特定節點自動執行。它透過 stdin 收到 JSON 資料，透過 exit code 和 stdout 回覆決策。

2.2 Hook 的生命週期事件

Claude Code 提供多個生命週期事件，以下是最常用的：

使用者開啟 Claude Code
        │
        ▼
  ┌─────────────┐
  │ SessionStart │ ← 一次性初始化（注入環境、設定）
  └──────┬──────┘
         │
         ▼  使用者輸入 prompt
  ┌──────────────────┐
  │ UserPromptSubmit  │ ← 可阻斷：拒絕不合理的 prompt
  └──────┬───────────┘
         │
         ▼  Claude 要呼叫工具（Edit、Bash 等）
  ┌──────────────┐
  │  PreToolUse   │ ← 可阻斷：拒絕危險操作（例如編輯 .env）
  └──────┬───────┘
         │
         ▼  工具實際執行
  ┌──────────────┐
  │  PostToolUse  │ ← 不可阻斷，但可回饋資訊（格式化、記錄狀態）
  └──────┬───────┘
         │
         ▼  Claude 準備停止回應
  ┌──────────────┐
  │     Stop      │ ← 可阻斷：品質關卡未通過就不讓停
  └──────────────┘
事件觸發時機能否阻斷？典型用途
SessionStartSession 啟動否注入命名空間提示
UserPromptSubmit使用者送出 prompt✅ 是過濾/修改 prompt
PreToolUse工具呼叫前✅ 是 (exit 2)安全防護
PostToolUse工具呼叫後否格式化、狀態追蹤
StopClaude 停止回應✅ 是 (exit 2)品質閘門
SubagentStop子代理完成✅ 是驗證子代理結果
TaskCompleted任務標記完成✅ 是完成度驗證

2.3 資料流：stdin / stdout / exit code

每個 Hook 都遵循相同的通訊協定，就像 UNIX 管道一樣簡單：

Claude Code 引擎
     │
     │  stdin（JSON 格式）
     ▼
┌───────────────────────────────┐
│       你的 Hook 腳本           │
│                               │
│  1. 從 stdin 讀取 JSON        │
│  2. 解析 tool_name、tool_input │
│  3. 執行你的邏輯              │
│  4. 決定：允許 or 拒絕        │
│                               │
└───────────────────────────────┘
     │
     │  exit code + stdout JSON + stderr 訊息
     ▼
Claude Code 引擎

輸入格式（stdin JSON）

不同事件有不同欄位，但共用基礎結構：

// PreToolUse 事件的 stdin 範例
{
  "session_id": "sess_abc123",
  "transcript_path": "/tmp/.claude/sessions/abc123.jsonl",
  "cwd": "/home/user/my-project",
  "tool_name": "Edit",               // ← 哪個工具被呼叫
  "tool_input": {                        // ← 工具的輸入參數
    "file_path": "/home/user/my-project/.env",
    "old_string": "API_KEY=xxx",
    "new_string": "API_KEY=yyy"
  }
}

輸出：Exit Code 決定一切

Exit Code意義Claude 的反應
0 ✅ 允許 解析 stdout JSON（如有），繼續執行
2 🚫 阻斷 停止該操作，stderr 文字會回饋給 Claude 作為錯誤訊息
其他 ⚠️ 軟錯誤 繼續執行，stderr 寫入 verbose log 
# 範例 A：允許（exit 0）
echo '{"ok": true}'
exit 0

# 範例 B：阻斷（exit 2），stderr 回饋給 Claude
echo "[Guard] Blocked: editing .env is not allowed" >&2
exit 2

# 範例 C：允許但附帶警告
echo '{"systemMessage": "Warning: this file is shared by 3 services"}'
exit 0

2.4 hooks.json 註冊結構

Hook 可以在四個位置註冊（優先順序高→低）：

位置範圍適用場景
~/.claude/settings.json全域使用者個人通用 hooks
.claude/settings.json專案共享團隊共用 hooks（進 git）
.claude/settings.local.json專案私有個人專案 hooks（不進 git）
Plugin hooks/hooks.json外掛附帶外掛自帶 hooks

hooks.json 三層結構

{
  "hooks": {
    "<事件名稱>": [            // 第 1 層：事件
      {
        "matcher": "Edit|Write",  // 第 2 層：Regex 過濾工具名稱
        "hooks": [                  // 第 3 層：Hook handlers
          {
            "type": "command",       // command | http | prompt | agent
            "command": "path/to/script.sh",
            "timeout": 30            // 超時秒數（預設 60）
          }
        ]
      }
    ]
  }
}

Matcher 範例

Matcher匹配對象
""（空字串）所有工具（萬用）
"Edit|Write"Edit 或 Write 工具
"Bash"只匹配 Bash 工具
"mcp__codex__.*"所有 Codex MCP 工具
"mcp__.*"所有 MCP 工具

2.5 實戰：從零寫一個 Hook

🎯 目標

寫一個 PreToolUse Hook：禁止 Claude 刪除超過 50 行的程式碼（防止大規模誤刪）

1
建立腳本檔案

在專案根目錄建立 .claude/hooks/delete-guard.sh：

#!/usr/bin/env bash
# PreToolUse hook: 防止刪除過多程式碼
set -euo pipefail

# 從 stdin 讀取 JSON
INPUT=$(cat)

# 只攔截 Edit 工具
TOOL_NAME=$(echo "$INPUT" | jq -r '.tool_name // empty')
if [[ "$TOOL_NAME" != "Edit" ]]; then
  exit 0  # 不是 Edit，放行
fi

# 取出 old_string（要被替換的內容）
OLD_STRING=$(echo "$INPUT" | jq -r '.tool_input.old_string // empty')
NEW_STRING=$(echo "$INPUT" | jq -r '.tool_input.new_string // empty')

# 計算行數差異
OLD_LINES=$(echo "$OLD_STRING" | wc -l)
NEW_LINES=$(echo "$NEW_STRING" | wc -l)
DELETED=$(( OLD_LINES - NEW_LINES ))

# 刪除超過 50 行？阻斷！
if (( DELETED > 50 )); then
  echo "[Delete Guard] 阻斷：嘗試刪除 ${DELETED} 行（上限 50）" >&2
  exit 2  # 阻斷！
fi

exit 0  # 放行
2
賦予執行權限
chmod +x .claude/hooks/delete-guard.sh
3
註冊到 settings.json

編輯 .claude/settings.json（或 settings.local.json）：

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit",
        "hooks": [
          {
            "type": "command",
            "command": ".claude/hooks/delete-guard.sh"
          }
        ]
      }
    ]
  }
}
4
測試

重啟 Claude Code，嘗試讓 Claude 刪除大段程式碼，你會看到：

[Delete Guard] 阻斷：嘗試刪除 87 行（上限 50）

Claude 會收到這個錯誤訊息，並改用更小範圍的修改策略。

⚠️ 前置需求

所有 command 類型 Hook 都需要系統安裝 jq（JSON 處理工具）。
安裝方式：brew install jq（macOS）/ apt install jq（Linux）/ choco install jq（Windows）

2.6 本專案的 5 個 Hooks 詳解

Hook事件Matcher功能
namespace-hint SessionStart "" 告訴 Claude 所有指令要加 /sd0x-dev-flow: 前綴
pre-edit-guard PreToolUse Edit|Write 阻擋 .env、.git/、shell 注入路徑
post-edit-format PostToolUse Edit|Write 自動 prettier + 更新 review state（失效 review）
post-tool-review-state PostToolUse Bash|mcp__codex__* 解析 review/precommit sentinel，更新狀態檔
stop-guard Stop "" 檢查品質關卡是否通過，未通過則警告/阻止

狀態檔：.claude_review_state.json

這是 Hooks 之間共享的「記憶體」，記錄當前 session 的品質狀態：

{
  "has_code_change": true,       // ← post-edit-format 設定
  "has_doc_change": false,
  "code_review": {
    "executed": true,              // ← 是否執行過
    "passed": true,                // ← 是否通過
    "last_run": "2026-03-05T10:00:00Z"
  },
  "doc_review":  { "executed": false, "passed": false },
  "precommit":   { "executed": true,  "passed": true }
}
💡 關鍵設計

每次編輯都會「失效」review：post-edit-format 在偵測到程式碼修改時，會把 code_review.passed 和 precommit.passed 重設為 false。這確保即使上一輪 review 通過了，新的修改也必須重新審查。

3. Claude Code 作為 MCP

3.1 MCP 協定基礎

MCP（Model Context Protocol）是 Anthropic 推出的開放標準，定義 AI 模型與外部工具的結構化通訊。

┌───────────────┐      JSON-RPC 2.0       ┌───────────────┐
│   MCP Client   │  ◄──────────────────►  │   MCP Server   │
│  （AI 模型）    │   over stdio or HTTP    │  （工具提供者） │
└───────────────┘                          └───────────────┘

MCP Server 提供三種能力：

能力描述範例
Tools可呼叫的函式read_file、search_code、run_test
Resources可讀取的資料DB schema、API 文件
Prompts可重用的 prompt 範本Code review 範本

3.2 Claude Code 作為 MCP Client（日常使用）

這是最常見的模式。Claude Code 連接外部 MCP Server 來擴展能力：

┌──────────────────────────────────────────────────┐
│              Claude Code (MCP Client)              │
│                                                    │
│  內建工具：Read, Edit, Bash, Grep, Glob, Write     │
│                                                    │
│  ┌──── MCP 連線 ──────────────────────────────┐  │
│  │                                              │  │
│  │  mcp__codex__codex      →  Codex CLI Server  │  │
│  │  mcp__github__*         →  GitHub Server      │  │
│  │  mcp__pinecone__*       →  Pinecone Server    │  │
│  │  mcp__memory__*         →  Memory Server      │  │
│  │                                              │  │
│  └──────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────┘

本專案的 /codex-review-fast 就是透過 MCP 呼叫 Codex：

// Claude 呼叫 Codex MCP 進行 code review
mcp__codex__codex({
  prompt: `You are a senior Code Reviewer...
## Git Diff
\`\`\`diff
${GIT_DIFF}
\`\`\`
## ⚠️ You must independently research the project ⚠️
...`,
  sandbox: 'read-only',        // Codex 只能讀，不能改
  'approval-policy': 'never',  // 不需要人工核准
});
// 回傳: { threadId: "abc123", content: "## Findings\n..." }

3.4 Hooks vs MCP 比較

面向MCPHooks
方向Outside-in（外部引入能力）Inside-out（內部控制行為）
觸發者Claude 主動請求系統自動觸發
能否阻斷？否（只能回傳錯誤）是（exit 2 拒絕）
通訊協定JSON-RPC 2.0 over stdio/HTTPstdin JSON + exit code
狀態無狀態（每次獨立請求）可持久狀態（.json 檔案）
典型用途連接 GitHub、DB、Codex格式化、品質閘門、安全防護
一句話擴展「能做什麼」控制「該怎麼做」
💡 交叉點

本專案的 post-tool-review-state.sh 同時監控 Bash 和 mcp__codex__codex 工具——這是 Hook 監控 MCP 行為 的具體實例。Hook 可以攔截任何 MCP 工具的輸出，解析其結果來更新內部狀態。

4. Auto-Loop 控制流深度解析

4.1 雙層防禦架構

Auto-Loop 的可靠性來自「不信任單一層」的防禦思維：

┌─────────────────────────────────────────────────────┐
│  第一層：行為層（Rules + CLAUDE.md）                  │
│                                                      │
│  rules/auto-loop.md 告訴 Claude：                    │
│  「編輯後必須在同一回覆中跑 review」                  │
│                                                      │
│  ✅ 優點：Claude 會主動執行                          │
│  ❌ 弱點：Claude 可能忘記、被截斷、被其他指令覆蓋    │
├─────────────────────────────────────────────────────┤
│  第二層：系統層（Hooks）                              │
│                                                      │
│  hooks/stop-guard.sh 在 Claude 停止時檢查：          │
│  「review + precommit 是否都通過了？」                │
│                                                      │
│  ✅ 優點：系統強制執行，不依賴 AI 的記憶力            │
│  ❌ 弱點：只能在 Stop 時攔截，不能主動觸發 review    │
└─────────────────────────────────────────────────────┘

                    兩層合在一起 =
     行為層讓 Claude 「想做」+ 系統層讓 Claude 「必須做」

4.2 完整資料流追蹤（逐步）

以一次典型的程式碼修改為例，追蹤每個步驟的資料流向：

Step 1：Claude 編輯程式碼

1
PreToolUse → pre-edit-guard.sh

Claude 要 Edit src/app.ts → hook 收到 stdin JSON → 檢查路徑安全 → exit 0（放行）

2
PostToolUse → post-edit-format.sh

Edit 執行完成，hook 自動觸發：

  1. 偵測到 .ts 副檔名 → 執行 npx prettier --write src/app.ts
  2. 更新狀態檔：has_code_change = true
  3. 失效 review：code_review.passed = false、precommit.passed = false
# post-edit-format.sh 的關鍵邏輯
if echo "$file_path" | grep -Eq '\.(ts|tsx|js|jsx|...)$'; then
  update_change_flag "has_code_change"     # → true
  invalidate_review "code_review"          # → passed = false
  invalidate_review "precommit"            # → passed = false
fi

Step 2：Claude 自動跑 review（行為層觸發）

3
Claude 執行 /codex-review-fast

行為層（auto-loop.md）告訴 Claude 必須在同一回覆中跑 review：

  1. Claude 執行 git diff HEAD 收集變更
  2. Claude 呼叫 mcp__codex__codex 送出 diff 給 Codex
  3. Codex 獨立研究專案，回覆 findings + gate
4
PostToolUse → post-tool-review-state.sh

Hook 攔截 Codex MCP 的回覆，解析 sentinel：

# 假設 Codex 回覆包含 "⛔ Blocked"
if echo "$TOOL_OUTPUT" | grep -qE '⛔ Blocked'; then
  update_state "code_review" "true" "false"
  # → code_review = { executed: true, passed: false }
fi

Step 3：修正 → 重新 review → 通過

5
Claude 修正問題 → 再次觸發 edit hook → 再次失效 review

Edit 觸發 post-edit-format → code_review.passed = false（再次失效）

6
Claude 執行 /codex-review-fast --continue <threadId>

這次 Codex 回覆 ✅ Ready → hook 更新 code_review.passed = true

7
Claude 執行 /precommit

precommit-runner.js 執行 lint:fix → build → test:unit
全部通過 → 輸出 ## Overall: ✅ PASS → hook 更新 precommit.passed = true

Step 4：Stop Guard 放行

8
Claude 停止回應 → Stop → stop-guard.sh

讀取狀態檔：

{
  "has_code_change": true,
  "code_review":  { "passed": true  },  ← ✅
  "precommit":    { "passed": true  }   ← ✅
}
→ 所有關卡通過 → exit 0 → 允許停止

4.3 Sentinel 標準與解析

Review 指令和 precommit 必須輸出標準化的「哨兵字串」，hook 用它判斷通過/失敗：

Sentinel意義產生者消費者
✅ ReadyCode review 通過/codex-review-fastpost-tool-review-state
⛔ BlockedCode review 失敗/codex-review-fastpost-tool-review-state
✅ MergeableDoc review 通過/codex-review-docpost-tool-review-state
⛔ Needs revisionDoc review 失敗/codex-review-docpost-tool-review-state
## Overall: ✅ PASSPrecommit 通過/precommitpost-tool-review-state
## Overall: ❌ FAILPrecommit 失敗/precommitpost-tool-review-state
✅ All Pass所有檢查通過通用stop-guard (fallback)
⚠️ Need Human需要人工介入Doc Sync行為層 only
⚠️ 重要：Sentinel 的解析規則

post-tool-review-state.sh 使用優先順序解析：

  1. 先看是否有 ## Document Review 區段標題 → doc review
  2. 再看 ✅ Ready / ⛔ Blocked → code review
  3. 再看 ## Overall: → precommit
  4. 最後 ✅ All Pass → 通用 fallback

這避免了 code review sentinel 被誤認為 doc review sentinel。

4.4 失敗路徑與安全閥

場景 A：Claude 忘記跑 review 就想停

Claude: [Edit 完成]
        ↓
        「修改完成了。」
        ↓
        [嘗試停止]
        ↓
Stop → stop-guard.sh
        ↓
        讀取 .claude_review_state.json
        has_code_change = true
        code_review.passed = false  ← ❌
        precommit.passed = false    ← ❌
        ↓
        MISSING = "/codex-review-fast /precommit"
        ↓
  ┌─── warn 模式（預設）───────────────────────────┐
  │ stderr: "WARN: Missing steps..."                │
  │ exit 0 → 允許停止，使用者看到警告               │
  └────────────────────────────────────────────────┘
  ┌─── strict 模式 ───────────────────────────────┐
  │ stderr: "STRICT: Missing steps..."              │
  │ exit 2 → 阻止停止！Claude 被迫繼續跑 review   │
  └────────────────────────────────────────────────┘

場景 B：Review 失敗，修了 3 次仍不過

行為層有 3 round 限制：

# auto-loop.md 定義的退出條件
Round 1: Review ⛔ → Fix → Re-review ⛔
Round 2: Fix → Re-review ⛔
Round 3: Fix → Re-review ⛔
         ↓
         🔄 同一問題 3 rounds → 回報 blocker，請求人工介入

場景 C：Stale-State 修復

如果使用者在 Claude 之外做了 git commit，state file 的 has_code_change 仍為 true。Stop Guard 會用 git status 做反向校正：

# stop-guard.sh 的 stale-state 邏輯
GIT_PORCELAIN=$(git status --porcelain -uno)

# 如果 state 說有程式碼變更，但 git 沒有 .ts/.js 等檔案
if [[ "$HAS_CODE_CHANGE" == "true" ]]; then
  if ! echo "$GIT_PORCELAIN" | grep -qE '\.(ts|tsx|js|jsx|...)$'; then
    HAS_CODE_CHANGE="false"  # 覆寫：已 commit 或 revert
  fi
fi

# ⚠️ 注意：只做 true→false，不做 false→true
# 因為外部 untracked 檔案不應該觸發 review

6. 常見問題 FAQ

Q1：Hook 和 Git Hook 有什麼不同？

Git Hook 只在 git 操作（commit、push）時觸發。Claude Code Hook 在 AI agent 的整個生命週期觸發——包括讀檔、編輯、搜尋、停止等所有動作。

Q2：Hook 失敗會不會讓 Claude Code 掛掉？

不會。非 0 非 2 的 exit code 只會記錄到 verbose log，Claude Code 繼續運作。只有 exit 2 會阻斷操作。

Q3：多個 Hook 的執行順序？

同一事件的多個 Hook 按定義順序依序執行。任何一個 exit 2 就會阻斷，不會繼續執行後續 Hook。

Q4：我可以用 Python/Node.js 寫 Hook 嗎？

可以！"command": "python3 .claude/hooks/my-hook.py" 或 "command": "node .claude/hooks/my-hook.js"。只要能讀 stdin、寫 stdout、設 exit code 就行。

Q5：strict 模式和 warn 模式的差別？

warn（預設）：Stop Guard 發現缺步驟時顯示警告，但允許停止。
strict：發現缺步驟時 exit 2 阻止停止，Claude 被迫繼續執行。
設定方式：STOP_GUARD_MODE=strict

Q6：Codex MCP 一定要安裝嗎？

不是必要的。Codex MCP 是「選用」的外部 reviewer。沒有 Codex，/codex-review-fast 等指令無法使用，但其他功能正常。

Q7：如果我不想用 Auto-Loop，可以關掉嗎？

可以。設定 HOOK_BYPASS=1 環境變數會跳過所有 Stop Guard 檢查。或者移除 rules/auto-loop.md 來停用行為層規則。

Q8：如何除錯 Hook？

設定 HOOK_DEBUG=1 環境變數，Hook 會在 stderr 輸出詳細的 debug 資訊。你也可以直接手動測試：

# 手動測試 hook（模擬 stdin）
echo '{"tool_name":"Edit","tool_input":{"file_path":".env"}}' \
  | bash .claude/hooks/pre-edit-guard.sh
echo "Exit code: $?"
